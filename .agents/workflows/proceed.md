# Proceed 實作與驗證工作流程

本工作流程負責將 `PLAN.md` 與 `TASKS.md` 規劃轉化為實質程式碼實作。秉持嚴謹的門檻檢查與原子化執行原則，確保每一步驟皆具備充分的知識依據 (`KEEP.md`)，並在全部任務實作與驗證完成後引導進入 `/review` 階段。

## 執行步驟 (Workflow Steps)

### 步驟 1：前置產出物檢查 (Prerequisite Gate)
在展開任何程式碼異動前，必須先驗證前面的所有產出物是否齊備：
1. **檢查主題資料夾**：專案根目錄下是否存在目標 `issues/<topic-folder>/`。
2. **檢查核心三產出物**：
   - `issues/<topic-folder>/REQUIREMENT.md`（需求規格書）
   - `issues/<topic-folder>/PLAN.md`（實作架構計畫）
   - `issues/<topic-folder>/TASKS.md`（待辦任務清單）
3. **未通過門檻之處置（強制中斷）**：
   - 若缺少 `REQUIREMENT.md`：**拒絕執行**，提示使用者先執行 `/grill-me` 進行需求訪談對齊。
   - 若缺少 `PLAN.md` 或 `TASKS.md`：**拒絕執行**，提示使用者先執行 `/plan` 完成架構規劃與任務拆解。

### 步驟 2：知識點門檻檢查 (KEEP.md Gate)
在實作具體任務之前，必須確保具備可靠且充分的先驗知識依據：
1. **檢查 `KEEP.md`**：
   - 檢查專案根目錄或全域是否具備 `KEEP.md`，並檢索本次任務涉及的關鍵技術、外部套件或協定知識點。
   - **知識點標準**：此處的知識點必須是**官方文件說明、文獻、工具程式碼或重點描述**。
2. **缺乏知識點時的處置（嚴禁私自補充）**：
   - 若缺乏對應的官方文件或技術知識點，**強制拒絕執行**。
   - **切勿私自生成內容補充**（避免幻覺或未經查證的知識）。
   - 向使用者明確回報：「目前缺乏本任務關鍵技術的官方文件或權威知識依據，無法確保實作正確性。」
   - 明確引導使用者：「請先進行 `/discuss` 進行知識驗證與補充，記錄至 `KEEP.md` 後再繼續推進實作。」

### 步驟 3：原子化單一任務實作 (One Task at a Time)
1. **嚴格單一聚焦**：
   - 檢視 `issues/<topic-folder>/TASKS.md`，選取清單中**第一個未打勾的任務** (`- [ ]`)。
   - **一次只能執行一個任務**，嚴禁跨任務或一次實作多個項目。
2. **實作與本機驗證**：
   - 依據 `PLAN.md` 定義的規格修改/建立程式碼。
   - 針對該任務執行相對應的單元測試或指令進行驗證，確保程式能編譯、通過測試且無破壞既有功能。
3. **任務勾選與進度更新**：
   - 該任務實作並驗證成功後，立即將 `issues/<topic-folder>/TASKS.md` 中該任務標記為打勾：
     ```markdown
     - [x] 任務名稱：已完成內容與驗收說明
     ```
   - 向使用者回報該任務已完成及其驗證結果。

### 步驟 4：循環推進或推進審核 (Loop or Proceed to Review)
1. **若仍有未完成任務 (`- [ ]`)**：
   - 向使用者回報目前進度，詢問是否繼續推進下一個任務。
2. **若所有任務皆已打勾 (`- [x]`)**：
   - 向開發者明確回報：「`TASKS.md` 中的所有任務皆已實作並驗證完成！」
   - **推進至審查階段**：引導開發者執行 `/review`，由審查流程進行整體驗證、端到端測試並產出成果展示書 (`WALKTHROUGH.md`)。
